## GREEN evidence

- `capability_route` now reserves route ID + TTL first, runs deterministic DMF preflight using that same identity, then invokes the capability router and persists the final route with the reservation.
- The stored route context carries only bounded memory snapshot identity/provenance: memory context ID, snapshot hash, hard-guardrail IDs/details, and enforcement flag. Full evidence remains in the persisted memory context.
- Route response now returns `memoryStatus`, `memoryContextId`, `memorySummary`, `blockingGuardrails`, `openConflicts`, `priorFailures`, `relatedDecisions`, deterministic `memoryConfidence`, and `memorySnapshotHash`.
- `ROUTE_MEMORY_GUARDRAIL_BLOCKED` is emitted by operational route validation with exact memory/revision/key/source provenance when structured hard enforcement is explicitly enabled.
- `AGENT_CORE_MEMORY_ENFORCE_HARD_GUARDRAILS` defaults to `false`, preserving observe-only rollout unless deliberately enabled.
- Memory preflight failure degrades memory status and never fabricates evidence; capability routing still proceeds.
- Persisted memory contexts are invalidated by the same route TTL through principal-bound expiry filtering.
- Existing routing behavior is preserved in two cases: DMF disabled, and DMF enabled with an empty/no-relevant-memory database.
