## Scope completed

- DMF is enabled by default through `AGENT_CORE_MEMORY_ENABLED` fallback `true`; structured hard-guardrail enforcement remains opt-in/default `false`.
- Agent Core warms the in-process memory worker during service startup. No second console, server, database daemon, or separate memory service was introduced.
- Unified tray launcher explicitly pins `AGENT_CORE_MEMORY_ENABLED=true` and `AGENT_CORE_MEMORY_DB_PATH=<root>\runtime\memory\agent-core-memory.sqlite` into the existing Agent Core child process.
- `/health` reports memory enabled/healthy/state/integrity metadata while keeping overall Agent Core health independent from an unhealthy memory DB.
- `agent_core_status` reports authenticated principal/project-scoped memory diagnostics.
- Tray probes surface `Memory: Healthy|Degraded|Disabled|Unavailable` separately from MCP/tunnel health, preventing a degraded memory database from being mistaken for an unavailable Agent Core listener.
- Clean Agent Core close still checkpoints/truncates WAL before SQLite close, and launcher/service restart rehydrates the same database automatically.
- Corrupt memory DB startup is fail-closed for DMF: memory becomes `degraded`, `capability_route` returns no fabricated context/evidence, while OAuth discovery, MCP, and the HTTP listener remain available.
- Listener-bind startup failure (`EADDRINUSE`) now closes the already-warmed memory worker before rethrowing, preventing leaked SQLite/WAL handles.
